# Site Analysis & Feasibility

Turn raw site evidence into a traceable feasibility picture before design. Work from survey/GIS/authority/client evidence; mark absent inputs UNKNOWN.

## Preflight

- Site boundary/area, survey datum, north, contours/topography and coordinate system.
- Access, transport, utilities, easements, rights-of-way, trees/ecology, heritage and adjacent uses.
- Climate/orientation, sun/wind, views, noise, flooding/drainage, geotechnical information and known hazards.
- Planning/zoning controls only when sourced through the applicable authority.

Keep verified facts, project assumptions, design options, and unresolved questions visibly separate. If a required input is absent, record it as `UNKNOWN` rather than inventing it.

## Workflow

1. Map evidence at regional, neighborhood and site scales; separate fact, inference and design opportunity.
2. Build constraints/opportunities and developable-envelope diagrams; never invent missing survey geometry.
3. Test program fit against sourced site controls, access, servicing, open-space and likely infrastructure needs.
4. Compare options using explicit criteria such as access, massing capacity, climate response, risk and phasing.

## Deliverables

- Site evidence register
- Constraints/opportunities matrix
- Site capacity and risk summary
- Recommended investigations and unresolved questions

## Verification

- Every dimensional/regulatory claim has a source or is labelled assumption.
- Coordinate, unit and area bases are explicit; conflicting sources are surfaced.

For file/model changes, compare the result against a pre-change baseline and report changed items, skipped items, failures, and checks actually run.

## Professional boundaries

- Do not replace cadastral/topographic/geotechnical/environmental surveys.
- Do not state planning approval, flood safety or geotechnical suitability as confirmed without competent review.

If a live CAD/BIM/GIS/analysis tool or MCP integration is available, inspect the current document/model and tool version before write operations. Prefer read-only inspection, dry runs, bounded samples, new output paths, and native undo/transaction mechanisms. Never claim a model or drawing was changed unless the tool confirms it.

If the native application is unavailable, produce a reproducible plan, script, structured data, SVG/DXF artifact, or exact in-application procedure instead of pretending to have operated the software.
