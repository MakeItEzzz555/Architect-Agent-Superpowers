# Interior & Fit-Out Design

Coordinate space, user experience, finishes, furniture/equipment and services without fabricating product or code data.

## Preflight

- Room program, occupancy, accessibility needs, existing shell/core, fixed services/structure, equipment and client standards.
- Finish performance requirements, budget/lead-time constraints and target documentation stage.

Keep verified facts, project assumptions, design options, and unresolved questions visibly separate. If a required input is absent, record it as `UNKNOWN` rather than inventing it.

## Workflow

1. Zone functions and circulation; test furniture/equipment clearances against sourced requirements.
2. Develop finish/material palette by performance, maintenance, acoustics, moisture, fire and visual intent.
3. Coordinate reflected ceiling, lighting, sprinklers/diffusers, access panels, signage and major joinery interfaces at the appropriate level.
4. Produce room/finish/equipment schedules and detail briefs; record long-lead or custom items.

## Deliverables

- Furniture/equipment plan
- RCP/lighting coordination brief
- Finish/material schedule
- Room data and joinery/detail briefs
- Fit-out issue checklist

## Verification

- Room IDs, levels, dimensions and schedules reconcile with architectural plans.
- Specified products and performance values are sourced and versioned.

For file/model changes, compare the result against a pre-change baseline and report changed items, skipped items, failures, and checks actually run.

## Professional boundaries

- Do not invent fire ratings, accessibility clearances or product certifications.
- Electrical/lighting calculations and life-safety layouts require qualified discipline verification.

If a live CAD/BIM/GIS/analysis tool or MCP integration is available, inspect the current document/model and tool version before write operations. Prefer read-only inspection, dry runs, bounded samples, new output paths, and native undo/transaction mechanisms. Never claim a model or drawing was changed unless the tool confirms it.

If the native application is unavailable, produce a reproducible plan, script, structured data, SVG/DXF artifact, or exact in-application procedure instead of pretending to have operated the software.
